# dsh-planner-worker

一个 DeepSeek Harness（DSH）的 agent 预设：把「规划」和「执行」拆成两个角色，并且**用工具权限强制分开**，不靠提示词劝。

队长只做判断和验收——它的写文件工具是关闭的，想改文件只能派子代理。
每个任务进清单、标难度；子代理必须带终态和证据回来；验收只看证据，不认「我完成了」。

|  | 普通 agent | 本预设 |
|---|---|---|
| 队长改文件 | 可以 | **不能**（write/edit 关闭） |
| 任务账本 | 无 | todo 清单 + 机械/常规/高难三档 |
| 子代理回报 | 自然语言总结 | `done / blocked / needs_human` + 证据（路径:行号、命令输出） |
| 验收依据 | 看它说完成了 | 抽查产物与命令输出 |
| 返工 | 再交代一遍 | 带归因标签（规格没说清/理解偏/能力不够/环境问题） |
| 失败循环 | 反复重试 | 同一件事两次停手、报状态 |

## 它不做什么

- 不做持久多 Bot、不做 Agent 间消息总线、不投票。
- 不引入新插件，装完即用：一个会话一个队长，子代理是临时的。
- 不保证队长永不动手：三四步能完的小事它仍会自己做，这是刻意留的口子。

## 装之前

- 需要 DSH Desktop（或支持 `agent-preset` 的 dsh）。包里只有预设定义和安装脚本，不带 DSH 本体，也不带任何模型服务。
- 装完必须重启一次 DSH 才会加载。

## 安装

解压后在本目录打开 PowerShell：

```powershell
.\install.ps1
```

脚本做两件事：

1. 读 `subagent-model.json`，决定子代理用哪个模型（见下一节）
2. 把 `plan-exec` 复制到 `%USERPROFILE%\.dsh\bundles\plan-exec`

然后重启 DSH，并把本地 bundle 挂进你的 profile：

```powershell
dsh plugin --profile default add "link:$env:USERPROFILE\.dsh\bundles\plan-exec"
```

`default` 换成你自己的 profile 名（一般是 `default` 或 `desktop`）。GUI 的插件页也可以直接选本地目录安装。

重启后新建会话，在预设下拉里选「规划-执行协作」。

## 子代理模型怎么配（重点）

只需要改一个文件：包里的 `subagent-model.json`。

```json
{
  "provider": "",
  "model": ""
}
```

- **都留空（默认）**：子代理跟随你当前会话选的模型。谁装都能跑，但不会省 token。
- **都填上**：子代理固定用这个模型，比如填你已注册的便宜模型。队长的贵模型只花在规划与验收上。

改完保存，重新运行一次 `.\install.ps1`，再重启 DSH。以后换模型也是改这个 json、重跑脚本，不用碰 YAML。

`provider` / `model` 必须是你的 DSH 里已经注册好的标识（`/model` 列表里显示的那个，不是界面上起的别名）。

`subagent_fork`（继承本会话上下文的派法）的模型始终跟随队长，不受这个文件影响。

## 怎么验证它生效了

新建一个会话、选这个预设，然后：

1. 问它「你这个会话能改文件吗」——应该回答不能，并说明只能派子代理。
2. 让它做个需要改文件的小任务——它应该先派 `subagent`，而不是直接 `edit`。
3. 看这轮的回复末尾——应该有一张任务清单，每条带状态和难度档。

如果它还是自己动手改文件，说明预设没挂上（检查预设下拉是否选中、是否重启过 DSH）。

## 方法论来源

这套规则不是拍脑袋定的，参考的是毛泽东方法论的工程化解读（实事求是、集中优势兵力、实践检验、调查研究这些），只保留能落成可观测行为的部分：

| 方法论要点 | 文档规则 | 预设里的落地 |
|---|---|---|
| 实事求是：一切从实际出发 | R-2.2 真实状态优先 | 只认终态和证据，不认「我完成了」 |
| 集中优势兵力，不平均用力 | R-3.2-01 按关键度分配 | 队长用贵模型只做规划与验收，执行派子代理 |
| 调度权归治理层 | R-3.3-01 调度权 | 派发、终止、验收权在队长，子代理只有执行权 |
| 积极防御：环路防御 | R-3.3-03 转手计数 | 同一件事两次停手、报状态，不原地重试 |
| 生产与验证分离 | R-3.4-02 审计独立 | 队长不生产，只验收 |
| 理论联系实际 | R-3.6-01 评审规则 | 验收必须引用具体产物或命令输出 |
| 压缩不失真 | R-3.5-02 结构化摘要 | 派活时关键参数原样粘贴，不要自己总结 |

文档本身不随本仓库分发（它包含大量与具体团队相关的案例）。这里只借它的规则编号体系，方便追溯每条规则为什么存在。这是工程类比，不涉及政治讨论。

一句话总结：**队长负责判断和验收，子代理负责生产，验收永远看外部证据。**

## 包里有什么

| 路径 | 作用 |
|---|---|
| `subagent-model.json` | 子代理模型设置（改这里，不用改 YAML） |
| `plan-exec/` | 预设定义（`package.json` + `cordis.patch.yml`） |
| `install.ps1` | 安装脚本（复制文件 + 把模型写进预设） |
| `README.md` | 本文件 |

## 局限

- 队长偶尔仍会自己做小事（这是刻意的例外口子，不是 bug）。
- 普通子代理不继承上下文，信息都靠队长在派活时写进 prompt；需要共享上下文时用 `subagent_fork`，但那会花和队长一样的模型成本。

## 卸载

删掉这个目录后重启 DSH：

- `%USERPROFILE%\.dsh\bundles\plan-exec`

如果已经用 `dsh plugin add` 挂过，先在插件页或命令行里移除该 bundle。
